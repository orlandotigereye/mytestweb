========================================================================
🧠 AI COGNITIVE OS CLI (teZ.js) 移載、部署與操作標準作業程序 (SOP_260701)
========================================================================

本文件說明如何將整合了 planA 工作流（Planner, Executor, Critic, Refiner, Sandbox, Embedding Memory）的
AI 認知系統命令列工具 (teZ.js) 進行移植、載入到任何新的乾淨環境中運行，並提供所有操作的標準作業程序 (SOP)。

────────────────────────────────────────────────────────────────────────
一、 移載必備檔案清單 (Minimum Directory Structure)
────────────────────────────────────────────────────────────────────────
在移載至新目錄或新電腦時，您必須複製以下結構的檔案：

[您的目的目錄]/
├── teZ.js                   # 認知系統主程式
├── version.json             # 版本控制檔 (JSON 格式，由 VersionManager 讀寫)
├── config/
│   └── config.js            # 連線、模型名稱及輸出目錄等設定檔
└── core/
    └── version.js           # 版本升級與管理邏輯

*註：`memory/` (對話歷史與語意記憶) 目錄可選擇性複製。若不複製，新環境會自動初始化一個空的記憶檔。
*註：`Proj/` 與 `backup/` 目錄不需複製，執行時會自動建立。

────────────────────────────────────────────────────────────────────────
二、 系統環境與相依性準備
────────────────────────────────────────────────────────────────────────
1. 安裝 Node.js 環境：
   - 本工具採用 Node.js 原生 API 撰寫（不需執行 npm install 安裝第三方套件）。
   - 請至官網安裝 Node.js (v18 或更新版本)。
   - 原生模組相依性說明：
     - `readline` (互動 CLI 用)
     - `fs` (檔案操作與備份用)
     - `path` (路徑解析與移載相容性)
     - `crypto` (生成 UUID 用)
     - `child_process` (沙盒測試執行程式用)

2. 本地 AI 推理環境安裝與啟動 (Ollama)：
   - 請至 https://ollama.com 下載並安裝 Ollama。
   - 啟動 Ollama 服務（預設連接埠為 11434）。
   - 打開終端機下載本工具預設的模型：
     > ollama pull qwen2.5:3b
     > ollama pull qwen2.5:7b
   *註：若要使用其他模型，請至 `./config/config.js` 修改 `MODEL_FAST` 及 `MODEL_SMART` 設定。

────────────────────────────────────────────────────────────────────────
三、 新環境部署與執行步驟
────────────────────────────────────────────────────────────────────────
1. 將「第一節」清單中的檔案複製到您目標主機的新資料夾內（如：C:\AI-OS\ 或 /usr/local/ai-os/）。
2. 開啟終端機（cmd、PowerShell 或 bash），切換目錄至該資料夾：
   > cd [您的目的目錄路徑]
3. 啟動 Ollama 服務。
4. 執行啟動指令：
   > node teZ.js
5. 當看到「🧠 AI COGNITIVE OS v5 STARTED」且出現「You ➔」提示符號時，即代表系統移載與啟動成功。

────────────────────────────────────────────────────────────────────────
四、 完整功能指令與操作標準作業程序 (SOP)
────────────────────────────────────────────────────────────────────────
在「You ➔」提示符號後輸入以下指令可進行對應的操作：

------------------------------------------------------------------------
SOP 1. 一般提問與自動程式開發 (PlanA Pipeline)
------------------------------------------------------------------------
- 目標：使用 AI 進行一般對話或自動生成、測試、修正程式碼。
- 步驟：
  1. 在 `You ➔` 後直接輸入您的需求或問題。
  2. 若系統偵測到與「程式、Code、寫、實作」等開發相關的關鍵字：
     a. 系統會自動啟動 **planA** 工作流。
     b. **Planner** 會生成執行計劃。
     c. **Executor** 會實作代碼並存入本地檔案。
     d. **Critic** 與 **Sandbox** 會在沙盒中自動執行代碼，檢測是否有執行期錯誤。
     e. **Refiner/Validator** 會根據 Critic 回饋進行自我糾錯迴圈，直到代碼通過或達上限。
  3. 對話與代碼將自動寫入語意記憶系統。

------------------------------------------------------------------------
SOP 2. 檔案分析與修改 (/file)
------------------------------------------------------------------------
- 目標：載入單一檔案的內容供 AI 分析、重構或除錯。
- 步驟：
  1. 輸入 `/file <檔案路徑> [選填指示詞]`。
     *系統已支援引號與空白路徑*（例如：`/file "C:\My Project\app.js" 幫我寫單元測試`）。
  2. 系統會讀取該檔案，並將其內容與您的指示包裝成 Context 發送給 AI。
  3. AI 分析完成後會將回應與代碼輸出，並自動在終端機渲染格式化後的內容。

------------------------------------------------------------------------
SOP 3. 專案/資料夾結構分析 (/folder)
------------------------------------------------------------------------
- 目標：讓 AI 快速掌握整個資料夾的代碼結構、模組關係與程式大綱。
- 步驟：
  1. 輸入 `/folder <資料夾路徑>`。
     *系統已支援引號路徑*（例如：`/folder "C:\My Project\src"`）。
  2. 系統會遞迴掃描該資料夾下所有檔案（自動忽略無關的 `node_modules` 等目錄），建立檔案結構樹。
  3. 生成整個專案的 Code Map（包含主要函數與類別定義大綱）載入 Context，讓 AI 取得專案全貌。

------------------------------------------------------------------------
SOP 4. 程式碼版本還原 (/rollback)
------------------------------------------------------------------------
- 目標：將被 AI 修改的程式碼還原回之前的版本。
- 步驟：
  1. 輸入 `/rollback <Proj資料夾下的檔名>`（例如：`/rollback main.js`）。
  2. 系統會在 `backup/` 目錄中尋找該檔案時間戳最新的一份 `.bak` 備份檔。
  3. 確認後，將備份檔覆蓋回 `Proj/` 對應路徑，復原代碼。

------------------------------------------------------------------------
SOP 5. 迴歸測試與系統自我驗證 (/test)
------------------------------------------------------------------------
- 目標：執行系統內建的 Regression Tests，驗證 AI Cognition 的完整性。
- 步驟：
  1. 輸入 `/test`。
  2. 系統會自動模擬系統生成任務、執行 sandbox 檢測並跑完完整測試套件。
  3. 終端機會輸出測試結果，若全部通過則代表認知引擎功能完好。

------------------------------------------------------------------------
SOP 6. 模型動態調整 (/model)
------------------------------------------------------------------------
- 目標：根據硬體能力與運算需求，切換使用的 AI 模型。
- 步驟：
  1. 輸入 `/model [fast | smart | dynamic]`。
     - `fast`：切換至輕量、回應快速的模型（如 3b）。
     - `smart`：切換至推理能力強、較重型的模型（如 7b）。
     - `dynamic`：由系統依輸入長度自動調配（大於 100 字自動用 smart，否則用 fast）。
     - 不帶參數：直接在 `fast` 與 `smart` 之間進行 Toggle 切換。
  2. 終端機會顯示當前設定的活動模型。

------------------------------------------------------------------------
SOP 7. 系統狀態監控與清理 (/runtime & /clear & /bump)
------------------------------------------------------------------------
- 顯示運行狀態：輸入 `/runtime` 可檢視執行時間、請求次數、記憶體圖結構的節點與邊數量、獎勵積分等。
- 清除記憶：輸入 `/clear` 可清除圖形記憶體與語意向量資料庫，重置系統狀態。
- 升級版本號：輸入 `/version` 或 `/bump`，系統會自動遞增並儲存當前專案的版本號。
- 輔助指令：輸入 `/help` 顯示簡易指令清單。
- 結束系統：輸入 `exit` 退出 CLI 介面。
